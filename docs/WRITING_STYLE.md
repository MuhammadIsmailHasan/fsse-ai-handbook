# Writing Style — Plain Words, More Analogies

Learner feedback: lessons were accurate but had **too many technical terms and not enough analogies**,
and English is not their first language. Every lesson (English and Bahasa Indonesia) follows these rules.
Pilot: `content/modules/m4/w1/07-async-javascript-and-fetch.md`.

## Rules

1. **Plain language.** Short sentences, common words, active voice. No idioms.
2. **Fewer terms.** Only the jargon the lesson needs. Each term gets a one-sentence meaning.
3. **🔤 Key words table first** (5–8 rows): *Word · In simple words · Bahasa Indonesia*
   (the Indonesian file uses *Istilah · Artinya (sederhana)*). It replaces the old Kamus at the end.
4. **An everyday analogy for each main idea** (1–2 sentences, Indonesian daily life is welcome:
   warung, ojek, antrean, satpam), then the real code.
5. **Shorter.** Merge "Why does this exist?" + "What happens if we DON'T?" into **❓ Why it matters**;
   fold trade-offs / when-to-use / industry into the steps, mistakes and best practices.
6. **Keep:** the three parts, exercises and hints, quick checks, 🏆 Best practices, English technical
   terms (the learner targets remote US jobs).

## Lesson outline

```text
::part[Learn the Concept]
  🎯 What you'll learn · 🔤 Key words · 🧠 The big idea · ❓ Why it matters
  📖 Step by step · ⚠️ Common mistakes · 🏆 Best practices
::part[Explain & Design]
  🗣️ Explain it · 📐 Design it (+ self-review)
::part[Toy Exercise]
  exercise · hints · ✅ Quick check · 📚 Keep learning
```
